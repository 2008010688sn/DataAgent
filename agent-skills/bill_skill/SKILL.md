# 应收账单分析 skill

当用户的问题涉及应收账单、账单明细、结算规则、费用、费用预测、账单差异、账单口径时，使用这个 skill。

## 工作原则

1. 不要在每一轮都调用工具。只有当回答明显依赖业务知识，或者你不确定业务口径时，才调用 `domain_business_knowledge.search`。
2. 默认优先检索 `businessKnowledge` 和 `agentKnowledge`。如果明确知道要查 FAQ、QA 或文档，可以通过 `knowledgeTypes` 缩小范围。
3. 将工具返回结果作为“证据”辅助推理，而不是机械复述；回答时要提炼规则、说明口径，并在必要时指出来源。
4. 如果检索结果为空或证据冲突，必须明确告诉用户当前知识不足，不能编造业务规则。
5. 当问题会影响 SQL 过滤条件、指标定义、分析步骤时，优先调用业务知识工具确认口径，再继续生成回答、计划或 SQL。

## 账单详情必填信息检查

当用户询问“具体账单详情”“账单明细”“每一个账单详情”“某张账单详情”“账单组成”“费用明细”“账单项明细”等需要定位到具体账单记录的问题时，必须先检测用户是否已经提供以下三个条件：

1. 客户：客户名称、客户简称、客户编码、客户 ID 之一。
2. 项目：项目名称、项目编码、项目 ID、项目简称之一。
3. 账单周期：账单月份、账期、结算周期、计费周期，或明确的开始日期和结束日期。

只有三个条件都明确后，才能继续检索知识、查询数据、生成 SQL 或分析账单明细。

如果缺少任一条件，不要猜测，也不要直接查询。应先用简短问题引导用户补充缺失条件，并只追问缺失项。

示例：

- 已有客户，缺项目和账单周期：`请补充项目和账单周期，例如：XX 项目，2026-05。`
- 已有客户和项目，缺账单周期：`请补充账单周期，例如：2026-05 或 2026-05-01 至 2026-05-31。`
- 三个条件都缺：`请提供客户、项目和账单周期，我再帮你查看具体账单详情。`

如果用户给出的是相对时间，例如“上月”“本月”“上个结算周期”，需要结合当前日期解析成明确账单周期；如果无法确定企业账期边界，先追问确认。

## 典型触发场景

- “客户结算模型是什么样的”
- “XX客户在下个月的预测费用”
- “查看某客户某项目 2026 年 5 月账单详情”
- “这个客户每一笔账单明细是什么”
- “帮我分析 XX 项目上月应收账单差异”
